#    (updated in blockchain.py) — verified against a real live POA chain

#    `Client` entirely (async-only now). Rather than making every Flask
#    route async, `blockchain.py`'s two Solana call sites

#    `AsyncClient` inside their own `asyncio.run()` call — every public
#    function in that module keeps its original synchronous signature, so
#    no caller (`candy_machine.py`, `contracts.py`, the blueprint routes)
#    needed to change at all.
#
# Verified against real live networks, not just the test suite: a real

# Solidity compilation (Phase 2). The old app imported `solcx` in
# smart_contract_deployer.py but never actually listed this package in
# requirements.txt — a preexisting gap, fixed here. On first use this
# downloads a solc binary (see app/services/solidity.py for why that's lazy
# now instead of happening at import time).
#
# Pinned to 2.0.5, not the original 2.0.3: found while getting a real local
# backend running — 2.0.3 hardcodes solc-bin.ethereum.org as the binary
# download host, a domain the Ethereum Foundation retired years ago (it has
# no DNS record at all anymore) in favor of binaries.soliditylang.org. Every
# compile call on 2.0.3 fails outright, regardless of environment — this
# isn't a sandbox-specific issue, it'd fail identically in production. 2.0.5
# points at the correct current host.
py-solc-x==2.0.5
